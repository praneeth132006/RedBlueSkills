02

"attack my application"

One instruction spins up a full authorized assessment. The orchestrator detects what your app is, builds a surface × technique matrix, and drives the whole library in kill-chain order.

  1. 00

    authorization gate

    Hard stop. Ownership, scope, window, and data-handling confirmed before a single active probe.

  2. 01

    fingerprint

    Maps stack, entry points, and session model into a surface map.

  3. 02

    select

    Lights up the matrix — routes each input to the skills whose preconditions it satisfies.

  4. 03

    run in kill-chain order

    Recon → injection → access control → auth → client-side. Minimal proof first.

  5. 04

    verify detection

    For every finding, checks whether the bound blue skill would actually catch it.

  6. 05

    report

    Prioritized findings, per-screen risk, reproduction, remediation, and coverage.

attack-my-application — sample report

03

zero to a report in five minutes

No security background needed. Install the library into your agent, point it at an app you own, and let it work.

zsh — your project
# 1 · install every skill + the orchestrator
$ npx redblueskills init

# 2 · read the 5-minute guide anytime
$ npx redblueskills quickstart

# or grab one skill — its pair comes along
$ npx redblueskills add web-sql-injection

  1. install

    init copies skills/ and orchestrators/ into ./.claude/skills/redblueskills.

  2. instruct

    Tell your agent: "attack my application at <url> — it's mine and I authorize testing."

  3. confirm the gate

    Ownership, scope, window, data-handling. A hard stop before anything active runs.

  4. read the report

    Findings, per-screen risk, coverage, and a fix list linked to each defense skill.

05

add your own pair

The library scales with contributors, not with one author. A red skill ships with the blue skill that detects it — and CI enforces that the pairing is real.

  1. copy the template

    cp -r _template skills/<app>/<team>/<stage>/<name>

  2. author both sides

    The offensive skill and the detection it pairs with — each one listing the other.

  3. validate

    Against _lab/ or a CTF target, then stamp who validated it and when.

  4. run the gate

    make check — schema, bidirectional pairing, catalog freshness, tests.

zsh — RedBlueSkills
$ make install
$ cp -r _template skills/web-app/red/…/my-skill
# …author SKILL.md + its paired blue skill…
$ make check     # the same gate CI runs
$ make catalog   # refresh catalog.json + INDEX.md
