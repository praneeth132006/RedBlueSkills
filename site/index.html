03

“Attack my application.”

One instruction spins up a full, authorized assessment. The orchestrator detects what your app is, builds a surface × technique matrix, and drives the whole library in kill-chain order.

  1. 00

    Authorization gate

    Hard stop. Confirms ownership, scope, window, and data-handling before a single active probe.

  2. 01

    Fingerprint

    Maps stack, entry points, and session model into a surface map.

  3. 02

    Select

    Lights up the matrix — routes each input to the skills whose preconditions it satisfies.

  4. 03

    Run in kill-chain order

    Recon → injection → access control → auth → client-side, minimal-proof first.

  5. 04

    Verify detection

    For each finding, checks whether the paired blue skill would catch it.

  6. 05

    Report

    Prioritized findings, per-screen risk, reproduction, remediation, and coverage.

05

Add your own pair.

The library scales with contributors, not with one author. A red skill ships with the blue skill that detects it — and CI enforces the pairing is real.

  1. Copy the template. cp -r _template skills/<app>/<team>/<stage>/<name>
  2. Author both sides. The offensive skill and the detection/hardening it pairs with — each lists the other.
  3. Validate against _lab/ or a CTF target, then stamp who validated it and when.
  4. Run the gate. make check — schema, bidirectional pairing, catalog freshness, tests.
zsh — RedBlueSkills
$ make install
$ cp -r _template skills/web-app/red/…/my-skill
# …author SKILL.md + its paired blue skill…
$ make check     # the same gate CI runs
$ make catalog   # refresh catalog.json + INDEX.md

06

The doctrine.

Four rules most “awesome-security” lists don’t give you.

A

Agent-native

Every skill is an executable SKILL.md with a machine-readable header — loadable by Claude Code and other agents, not just read by humans.

B

Paired red ↔ blue

Every offensive technique links to its detection. CI enforces the pairing is bidirectional. Offense you can’t detect doesn’t ship.

C

Validated & provenanced

Proven against a real lab or CTF target, stamped with who validated it and when, and auto-flagged stale after six months.

D

Tooled

A schema validator, catalog generator, and test suite gate every PR. Quality scales with contributors instead of rotting.

⚠ Authorized use only. These skills are for testing systems you own or are explicitly permitted to test, and for defending systems you operate. Read ETHICS.md first. You are responsible for staying within your authorization and the law.
