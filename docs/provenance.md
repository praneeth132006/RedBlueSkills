# Provenance & supply-chain integrity

RedBlueSkills is a security library, so it holds itself to the standard it asks of
its users: every artifact is **reproducible, hashed, and signed**, and nothing that
describes the library is written by hand.

## What ships

| Artifact | What it is | Generated by |
|---|---|---|
| [`catalog.json`](../catalog.json) | Machine-readable index of every skill | `make catalog` |
| [`sbom.cdx.json`](../sbom.cdx.json) | CycloneDX 1.5 SBOM — each skill a component with a SHA-256 and its risk/team/stage metadata | `make provenance` |
| [`provenance.json`](../provenance.json) | Per-skill content hash + who validated it, against which lab, when | `make provenance` |
| `site/badges/*.json` | shields.io endpoints for the README badges (counts) | `make catalog` |
| `site/coverage.svg` | surface × kill-chain heatmap | `make catalog` |

Every one is derived from the `SKILL.md` files on disk. There are **no hardcoded
counts** anywhere — `tools/build_catalog.py --check` and
`tools/build_provenance.py --check` run in CI and fail the build if any committed
artifact drifts from what the tree would produce.

## Determinism

The SBOM and provenance manifest contain **no timestamps and no clock-based UUIDs**.
The CycloneDX `serialNumber` is a UUIDv5 derived from the component hashes, so the
same tree always produces byte-identical files. That is what makes the `--check`
gate meaningful and what makes a signature verifiable: the bytes you verify are the
bytes anyone can reproduce from the source.

## Signing (cosign keyless)

Releases are signed in CI with [Sigstore cosign](https://docs.sigstore.dev/) in
**keyless mode** — there is no private key stored anywhere. The signing identity is
the GitHub Actions OIDC token for this repository, recorded in the certificate and
in the public Rekor transparency log. The release also carries a
[SLSA build provenance attestation](https://slsa.dev/) via
`actions/attest-build-provenance`.

### Verify a signed artifact

```bash
# from a downloaded release (provenance.json, .sig, .pem alongside it)
cosign verify-blob \
  --certificate-identity-regexp 'https://github.com/Security-Environment/RedBlueSkills' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --signature provenance.json.sig \
  --certificate provenance.json.pem \
  provenance.json
```

A successful verification proves the file was produced by this repository's release
workflow and has not been altered since.

### Verify a single skill against the manifest

```bash
python - <<'PY'
import json, hashlib, pathlib
man = json.load(open("provenance.json"))
bad = 0
for e in man["skills"]:
    got = hashlib.sha256(pathlib.Path(e["path"]).read_bytes()).hexdigest()
    if got != e["sha256"]:
        print("MISMATCH", e["name"]); bad += 1
print("ok" if not bad else f"{bad} mismatch(es)")
PY
```

## Re-proving validation

A `validated` stamp names the lab, the validator, and the date. Re-run the
self-contained labs any time:

```bash
make validate-labs        # offline labs (git+bash, stdlib Python)
python tools/replay_labs.py --all   # also labs needing Docker/cloud
```

Each lab asserts the paired attack **succeeds** against the vulnerable config and
is **blocked** by the hardened one — proving both halves of the red↔blue pair.
